# 7. Recurrent Neural Networks

## Why RNNs? Motivation

So far, feedforward networks map a **fixed-size input to a fixed-size output** in a single forward pass. This breaks down when dealing with sequential data, where:
- Input length varies (a sentence, a video clip)
- Output length varies (generating a caption word by word)
- Order matters (the meaning of a word depends on what came before)

RNNs address this by maintaining an **internal state** that accumulates information as the sequence is processed.

---

## Input/Output Configurations

The same RNN cell can be wired up in different ways depending on the task:

| Type | Example |
|---|---|
| One-to-one | Standard feedforward network |
| **One-to-many** | Image captioning (image → sequence of words) |
| **Many-to-one** | Sentiment classification (sequence of words → label) |
| **Many-to-many** | Video captioning, language modeling (sequence → sequence) |

This flexibility is a key strength of RNNs — the architecture adapts to the task.

---

## The Vanilla RNN

**Core idea:** maintain a hidden state $h_t$ that summarizes everything seen so far.

$$h_t = f_W(h_{t-1}, x_t)$$

For a vanilla RNN, the function $f_W$ is:

$$\boxed{h_t = \tanh(W_{hh} h_{t-1} + W_{xh} x_t)}$$

- $h_{t-1}$: hidden state from the previous step (the "memory")
- $x_t$: input at current step
- $W_{hh}$, $W_{xh}$: weight matrices **shared across all timesteps**

To produce an output at step $t$:
$$y_t = W_{hy} h_t$$

**Weight sharing** is what makes the model size independent of sequence length. The same weights process every token.

### Computational Graph

The graph unrolls over time. The same $W$ matrix fans into every timestep:

```
h0 → [f_W] → h1 → [f_W] → h2 → ... → hT
        ↑              ↑
       x1             x2
```

- **Many-to-many:** produce $y_t$ from $h_t$ at each step. Loss $L = \sum_t L_t$.
- **Many-to-one:** only read off $y$ from the final $h_T$. Used when you need a single summary (e.g., classification).
- **One-to-many:** single input $x$ at $t=1$; subsequent steps receive the **previous output** $y_{t-1}$ as input (zeros initially). This is *autoregressive* generation.

## Example: Character-Level Language Model

A concrete way to see RNNs in action: train on text, predict the next character.

**Setup:**
- Vocabulary: e.g., `[h, e, l, o]`
- Each character is encoded as a one-hot vector
- Training sequence: `"hello"` → model learns to predict `"ello"` given `"hell"`

**Note on one-hot inputs:** Multiplying by $W_{xh}$ just extracts the column of $W_{xh}$ corresponding to that character. So in practice, we insert an **embedding layer** $W_E$ that maps each token index directly to a learned dense vector. This is both more efficient and lets the model learn rich representations.

**At training time:** teacher-forced — use the ground-truth previous token as input.

**At test time:** sample from the softmax distribution over the vocabulary, feed that sample back in. This produces text *autoregressively*.

The model improves dramatically with training: random character soup → plausible words → coherent sentences (Andrej Karpathy's famous 2015 blog post demonstrated this on Shakespeare and Linux source code).

## Backpropagation Through Time (BPTT)

To train an RNN, we unroll the computational graph and run backprop through the entire sequence. Gradients flow **backwards through time** along the chain of hidden states.

**Problem:** For long sequences, storing all activations for the full unroll is memory-intensive and slow.

**Solution: Truncated BPTT**
- Process the sequence in fixed-length **chunks**
- Run forward and backward through one chunk, compute gradients, update weights
- **Carry the hidden state forward** across chunks (so context isn't lost)
- **Only backpropagate within** each chunk

This is a practical compromise: the model still sees long sequences, but gradient computation is bounded.

---

## Vanilla RNN Gradient Flow: The Problem

Why is training vanilla RNNs hard in practice? Look at the gradient:

$$\frac{\partial L_T}{\partial W} = \frac{\partial L_T}{\partial h_T} \left(\prod_{t=2}^{T} \frac{\partial h_t}{\partial h_{t-1}}\right) \frac{\partial h_1}{\partial W}$$

Each factor in the product is:

$$\frac{\partial h_t}{\partial h_{t-1}} = \tanh'(W_{hh} h_{t-1} + W_{xh} x_t) \cdot W_{hh}$$

This product is applied $T-1$ times. Without the nonlinearity, this is just $W_{hh}^{T-1}$:

- **Largest singular value of $W_{hh} > 1$** → gradients **explode** exponentially
- **Largest singular value of $W_{hh} < 1$** → gradients **vanish** exponentially

In practice, vanishing is the more insidious problem: the RNN cannot learn long-range dependencies because the gradient signal dies before it reaches early timesteps.

**Fix for exploding gradients: Gradient Clipping**
```python
grad_norm = np.sum(grad * grad)
if grad_norm > threshold:
    grad *= (threshold / grad_norm)
```

**Fix for vanishing gradients: Change the architecture → LSTM.**

## RNN Tradeoffs

**Advantages:**
- Handles variable-length inputs with no context limit (in principle)
- Model size stays fixed regardless of sequence length
- Symmetric weight application at every step

**Disadvantages:**
- Sequential computation — cannot be parallelized across time (contrast with Transformers)
- In practice, hard to learn dependencies over many steps (vanishing gradients)

## Searching for Interpretable Cells

After training an RNN on text, you can ask: *what does each hidden unit actually track?*

Karpathy, Johnson, and Fei-Fei (ICLR Workshop 2016) visualized cell activations on held-out text and found units that clearly track:
- **Quote detection** — fires when inside a quotation
- **Line length** — tracks position along a line of text
- **`if`-statement depth** — fires inside conditional blocks
- **Code indentation depth** — tracks nesting level

This suggests that despite being trained only on next-character prediction, RNNs learn structured representations. The hidden state is a real "memory" encoding useful context.

## Applications

### Image Captioning (One-to-Many)

To generate a caption for an image:
1. Pass the image through a **CNN** (e.g., VGGNet), removing the final classification head
2. Use the CNN feature vector $v$ to initialize the RNN hidden state via an extra weight matrix $W_{ih}$:

$$h_0 = \tanh(W_{xh} \cdot \langle\text{START}\rangle + W_{ih} \cdot v)$$

3. The RNN then generates words autoregressively until it outputs `END`

This is a **CNN → RNN** pipeline. The CNN encodes "what is in the image"; the RNN decodes it into language.

**Results:** Works well for common objects. Fails on unusual viewpoints, fine-grained categories, and rare concept combinations.

### Visual Question Answering (VQA)

Given an image and a natural-language question, produce an answer. Architecture:
- CNN encodes the image to a feature vector
- LSTM encodes the question to a feature vector
- The two vectors are combined (e.g., pointwise multiply), then passed through an MLP → softmax over answer choices

### Visual Dialog

An extension of VQA to multi-turn conversations about an image (Das et al., CVPR 2017).

## Multilayer RNNs

Just as deep feedforward networks outperform shallow ones, stacking multiple RNN layers improves expressiveness. The output of each layer serves as the input sequence to the next:

```
Outputs  →  →  →  →  →
Layer 3  →  →  →  →  →
Layer 2  →  →  →  →  →
Layer 1  →  →  →  →  →
Inputs
```

In practice 2–4 layers is typical for vanilla RNNs; LSTMs often use 3–4.

## Long Short-Term Memory (LSTM)

*Hochreiter & Schmidhuber, 1997.*

The core motivation: vanilla RNNs struggle to learn long-range dependencies due to vanishing gradients. LSTM addresses this with a **separate cell state** $c_t$ that information can flow through with minimal modification.

### The LSTM has two states:
- $c_t$: **cell state** — the long-term memory (like a "conveyor belt")
- $h_t$: **hidden state** — the short-term working memory, exposed to the outside

### Four gates (all computed from $h_{t-1}$ and $x_t$):

$$\begin{pmatrix} i \\ f \\ o \\ g \end{pmatrix} = \begin{pmatrix} \sigma \\ \sigma \\ \sigma \\ \tanh \end{pmatrix} W \begin{pmatrix} h_{t-1} \\ x_t \end{pmatrix}$$

| Gate | Activation | Role |
|---|---|---|
| $i$ — Input gate | sigmoid (0–1) | **Whether** to write new info to cell |
| $f$ — Forget gate | sigmoid (0–1) | **Whether** to erase the previous cell state |
| $o$ — Output gate | sigmoid (0–1) | **How much** of cell state to reveal as $h_t$ |
| $g$ — Gate gate | tanh (−1 to 1) | **How much** new information to write (the value) |

### State updates:

$$c_t = f \odot c_{t-1} + i \odot g$$
$$h_t = o \odot \tanh(c_t)$$

$\odot$ is elementwise multiplication.

**Intuition:** $f$ decides what to forget from $c_{t-1}$; $i \odot g$ writes new content; $o$ gates how much of $c_t$ is exposed as the output $h_t$.

### LSTM Gradient Flow

The key insight: backpropagation from $c_t$ to $c_{t-1}$ is **only an elementwise multiplication by $f$** — no matrix multiply by $W$, no tanh saturation. This creates an **uninterrupted gradient highway** through the cell state across time.

This is analogous to **ResNet skip connections**, which solved the same vanishing-gradient problem in the depth direction for CNNs.

### Does LSTM solve vanishing gradients?

Not completely. It makes it *much easier*:
- If $f=1, i=0$: cell state is preserved indefinitely — information can persist as long as needed
- Gradients are no longer forced through a repeated matrix multiply

In practice, LSTM still benefits from gradient clipping and careful initialization.

## Modern RNNs

Vanilla RNNs and LSTMs are largely superseded in NLP by Transformers. However, RNN-style architectures are experiencing a revival as **state space models (SSMs)**:

- **RWKV**, **Mamba** (Gu & Dao, 2023): reformulate the recurrence to allow parallel training while keeping linear inference time
- Main advantages over Transformers:
  - **Unlimited context length** (Transformers are quadratic in sequence length)
  - **Inference scales linearly** with sequence length

These models close much of the gap with Transformers on language benchmarks while being far more efficient for long sequences.

---

## Summary

| | Vanilla RNN | LSTM | Transformer |
|---|---|---|---|
| Long-range dependencies | Poor (vanishing gradients) | Better (cell state highway) | Excellent (attention) |
| Parallelism | Sequential only | Sequential only | Fully parallel in training |
| Context length | Unlimited (in theory) | Unlimited (in theory) | Fixed (quadratic cost) |
| Parameter count | Small | 4× vanilla RNN | Large |

Key takeaways:
- RNNs are a flexible family of architectures for sequential data
- The recurrence formula and weight sharing are what make them work
- Vanilla RNNs suffer from vanishing gradients — LSTM's cell state provides an additive (non-multiplicative) update path as a fix
- Truncated BPTT is the practical training algorithm for long sequences
- Modern SSMs (Mamba) revisit the RNN paradigm with better efficiency
