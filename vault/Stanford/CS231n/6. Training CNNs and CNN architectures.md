# Lecture 6: Training CNNs and CNN Architectures

Two broad topics: **how to build CNNs** (layers, activations, architectures, weight init) and **how to train CNNs** (data, transfer learning, hyperparameters).

---

## Part 1: How to Build CNNs

### CNN Components

A CNN is assembled from these layer types:
- **Convolution Layers** – learn spatial features via filters
- **Pooling Layers** – downsample spatially (max pool, avg pool)
- **Fully-Connected Layers** – global reasoning at the end
- **Normalization Layers** – stabilize training
- **Dropout** – regularization
- **Activation Functions** – introduce nonlinearities (placed after linear operators)

---

### Normalization Layers

**Why:** Activations can shift and scale during training, making optimization harder. Normalization layers stabilize the distribution of activations across layers.

**General recipe (e.g. LayerNorm):**
1. Normalize input: $\hat{x}_{i,j} = \frac{x_{i,j} - \mu_j}{\sqrt{\sigma_j^2 + \varepsilon}}$
2. Scale and shift using learned parameters: $y = \gamma \hat{x} + \beta$

Statistics ($\mu$, $\sigma$) are computed per sample; $\gamma$ and $\beta$ are learned per feature.

**Variants** (differ in *which* dimensions are normalized over):
- **LayerNorm** – over all features for each sample; used in Transformers
- **BatchNorm** – over the batch for each feature; common in CNNs
- **InstanceNorm** – over spatial dims per channel per sample; used in style transfer
- **GroupNorm** – over channel groups; useful when batch size is small

---

### Dropout

**Why:** Reduces co-adaptation of features and acts as a regularizer.

- During each **forward pass**, randomly set neurons to zero with probability $p$ (typically $p = 0.5$)
- Two interpretations:
  1. Forces the network to learn **redundant representations** — no single neuron can be relied upon
  2. Trains a **large ensemble** of models sharing parameters — an FC layer with 4096 units has $2^{4096} \approx 10^{1233}$ possible masks

**At test time:** All neurons are active. Scale activations so that:
$$\text{output at test time} = \mathbb{E}[\text{output at training time}]$$
i.e., multiply activations by $(1-p)$, or equivalently use **inverted dropout** (divide by $(1-p)$ at train time and do nothing at test time).

> **Pattern:** Train with randomness → test by averaging out randomness (same idea as data augmentation).

---

### Activation Functions

**Why:** Without nonlinearities, stacking linear layers collapses to a single linear transformation. Activations give CNNs their expressive power.

| Function | Formula | Pros | Cons |
|---|---|---|---|
| **Sigmoid** | $\sigma(x) = \frac{1}{1+e^{-x}}$ | Outputs in $[0,1]$, biological analogy | Saturates at large $\|x\|$ → kills gradients; not zero-centered |
| **ReLU** | $\max(0, x)$ | No saturation for $x > 0$; fast; ~6x faster convergence than sigmoid | Dead ReLUs when $x < 0$; not zero-centered output |
| **GELU** | $x \cdot \Phi(x)$ | Smooth around 0; performs well in practice (used in BERT, GPT) | More compute than ReLU; gradient → 0 for large negative values |

**In CNNs:** Activations are placed **after linear operators** (conv layers, FC layers).

### CNN Architectures

The "revolution of depth" — ILSVRC winners grew from ~8 layers (AlexNet, 2012) to 152 layers (ResNet, 2015).

#### VGGNet (Simonyan & Zisserman, 2014)
**Key idea:** Replace large filters with stacks of small (3×3) filters.

- **Architecture:** Only 3×3 conv (stride 1, pad 1) and 2×2 max pool (stride 2)
- Went from 8 layers (AlexNet) → 16–19 layers (VGG16/VGG19)
- Reduced top-5 error from 11.7% (ZFNet, 2013) → 7.3% (ILSVRC 2014)

**Why 3×3 filters?**
- Three stacked 3×3 conv layers have the **same effective receptive field as one 7×7 layer**
- But they are **deeper** → more nonlinearities → more expressive
- And **fewer parameters**: $3 \times (3^2 C^2) = 27C^2$ vs $7^2 C^2 = 49C^2$ for $C$ channels

#### ResNet (He et al., 2015)
**Problem:** Plain deeper networks performed *worse* than shallower ones — even on training error — so it's an **optimization problem**, not overfitting.

A 56-layer plain network had higher training and test error than a 20-layer one. Since the deeper model should be at least as good (it could learn identity maps for extra layers), the issue is that gradient-based optimization can't find the solution.

**Solution:** Residual (skip) connections.

Instead of learning $H(x)$ directly, learn the **residual** $F(x) = H(x) - x$, so:
$$H(x) = F(x) + x$$

If the optimal answer is identity, the network just needs to push $F(x) \to 0$, which is much easier to learn.

```
"Plain" block:        Residual block:
H(x)                  H(x) = F(x) + x
 |                     |
conv                  relu
relu                   |
conv                  conv ←──┐
 |                    relu    │ (identity shortcut)
 x                    conv    │
                       └─────+┘
                              x
```

**Full ResNet architecture:**
- Stack of residual blocks, each with two 3×3 conv layers
- Periodically **double the number of filters** and **halve spatial resolution** using stride 2
- Initial **stem** conv layer (7×7 conv, stride 2) before the residual blocks
- Available in depths: 18, 34, 50, 101, 152 layers

**Results:** 152-layer ResNet — 3.57% top-5 error on ImageNet; swept all ILSVRC'15 and COCO'15 tasks.

### Weight Initialization

**Why it matters:** The initial weight scale determines whether activations explode or vanish through layers, both of which cripple training.

- **Too small** (e.g. std = 0.01): Activations shrink toward zero in deeper layers → gradients vanish
- **Too large** (e.g. std = 0.05): Activations explode → gradients blow up

**Solution — Kaiming / MSRA Initialization** (He et al., 2015):
$$\text{std} = \sqrt{\frac{2}{D_{\text{in}}}}$$

The factor of 2 is a **ReLU correction** (ReLU zeros out half the inputs, so we compensate). This keeps activation variance stable across all layers.

> **Rule of thumb:** Use Kaiming init with ReLU/GELU; use Xavier init ($\text{std} = 1/\sqrt{D_{\text{in}}}$) with tanh/sigmoid.

## Part 2: How to Train CNNs

### Data Preprocessing

**Why:** Raw pixel values have different scales and means per channel. Un-normalized inputs make optimization harder and slower.

Standard approach:
- Subtract the **per-channel mean** (computed over training set)
- Divide by the **per-channel std**

This gives each channel approximately zero mean and unit variance.

---

### Data Augmentation

**Why:** Augmentation artificially expands the dataset and acts as regularization — inject randomness at train time, average it out at test time.

**Golden rule:** The augmented image should still look like its class to a human.

| Technique | Train-time | Test-time |
|---|---|---|
| **Horizontal flip** | Random flip | Fixed |
| **Random crop/scale** | Pick random $L \in [256, 480]$, resize short side to $L$, sample 224×224 patch | Average 10 crops at 5 scales: $\{224, 256, 384, 480, 640\}$ |
| **Color jitter** | Randomize brightness, contrast, saturation | Fixed |
| **Cutout** | Zero out a random rectangular region | Full image |

> Cutout works very well for small datasets (e.g. CIFAR-10) but is less common for large datasets like ImageNet.

---

### Transfer Learning

**Why:** Training from scratch requires large datasets. Pretrained models already learn general visual features (edges, textures, shapes) that transfer across tasks.

**Procedure:**
1. Train a large model on ImageNet (or internet-scale data)
2. Adapt to your target task by fine-tuning

**How much to fine-tune depends on your data:**

| | Similar dataset | Different dataset |
|---|---|---|
| **Very little data** | Linear classifier on final layer only | Try a different pretrained model, or collect more data |
| **Quite a lot of data** | Fine-tune all layers | Fine-tune all layers or train from scratch |

Lower layers learn generic features (edges, blobs); upper layers are more task-specific — so freeze lower layers when data is scarce.

> **Practical tip:** Deep learning frameworks (PyTorch `torchvision`, HuggingFace `timm`) provide "model zoos" of pretrained models. Use them.

---

### Hyperparameter Selection

**Why:** Neural networks are sensitive to learning rate, weight decay, architecture choices, etc. A systematic approach avoids wasting compute.

**Step-by-step process:**

1. **Check initial loss** – Sanity check before training. For softmax over $C$ classes, expect $\ln C$.
2. **Overfit a small sample** – Run on 5–10 samples. If loss doesn't go to ~0, there's a bug.
3. **Find a learning rate** – Use all training data, small weight decay. Try $\{10^{-1}, 10^{-2}, 10^{-3}, 10^{-4}, 10^{-5}\}$. Good LR causes loss to drop significantly within ~100 iterations.
4. **Coarse grid search** – Try a range of hyperparams, train for 1–5 epochs.
5. **Refine grid** – Narrow the range, train longer.
6. **Analyze learning curves** – (see below)
7. **Repeat from step 5.**

**Reading learning curves:**

| Pattern | Diagnosis |
|---|---|
| Both train and val accuracy still rising | Train longer |
| Large train/val gap | Overfitting — increase regularization or get more data |
| No train/val gap, both plateau early | Underfitting — try a bigger model or train longer |

**Random search vs. grid search:**
Random search is preferred over grid search when some hyperparameters matter much more than others. Grid search wastes evaluations on the unimportant dimensions; random search gets more coverage of the important ones. (Bergstra & Bengio, 2012)
