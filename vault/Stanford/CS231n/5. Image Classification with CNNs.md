# Image Classification with CNNs

## Summary

Linear classifiers fail at image tasks because they learn one flat template per class and destroy spatial structure by flattening images into vectors. CNNs fix this by operating directly in 2D image space using **convolution layers** and **pooling layers**. Two key design ideas make CNNs efficient: **local connectivity** (each neuron only looks at a small spatial patch) and **parameter sharing** (the same filter weights are reused at every position). Together these extract hierarchical features — edges and colors in early layers, larger structures like eyes and letters in deeper layers — while using far fewer parameters than a fully connected network. The entire system is trained end-to-end with backprop.

## 1. Why Not Linear Classifiers?

Linear classifiers have two fundamental problems for images:

| Viewpoint | Problem |
|---|---|
| **Visual** | Learns one template per class — can't capture the same object at different positions, angles, or lighting |
| **Geometric** | Can only draw linear decision boundaries in pixel space |

The deeper issue: when you flatten a 32×32×3 image into a 3072-dim vector to feed a linear layer, **all spatial structure is destroyed**. Pixels that were neighbors become unrelated entries in a vector.

A fully-connected neuron processing a 200×200×3 image would need 120,000 weights *per neuron* — this scales terribly and leads to rapid overfitting.

## 2. From Hand-Crafted Features to CNNs

### The old approach: feature engineering

Instead of feeding raw pixels to a classifier, people hand-designed transformations to extract meaningful structure first:

- **Color Histogram** — counts pixel colors across the image; rotation-invariant but loses all spatial info
- **Histogram of Oriented Gradients (HoG)** — divides the image into 8×8 cells, quantizes edge directions into 9 bins per cell. A 320×240 image → 40×30 bins × 9 values = **10,800-dimensional feature vector**

These features are then fed into a linear classifier.

### The CNN approach

CNNs **learn** their own features from data, end-to-end:

```
Old:  [Image] → [Hand-crafted features] → [Linear classifier] → scores
CNN:  [Image] → [Conv layers (learned features)] → [FC layers] → scores
```

The entire pipeline is trained with backprop + gradient descent. No manual feature engineering needed.

## 3. Brief History of CNNs

| Period | What happened |
|---|---|
| **1998** | LeCun et al. — gradient-based learning for document recognition (LeNet) |
| **2012** | AlexNet (Krizhevsky, Sutskever, Hinton) — deep CNNs dominate ImageNet; 16% top-5 error vs. 26% runner-up |
| **2012–2020** | CNNs dominate virtually all vision tasks: detection, segmentation, captioning, image generation |
| **2021–present** | Vision Transformers (ViT) take over; CNNs and Transformers are increasingly combined |

**Why transformers took over:** Originally designed for language (2017, "Attention is All You Need"), transformers scale more easily with data and compute. In 2021, ViT showed patches of images can be treated like word tokens — "An Image is Worth 16×16 Words."

## 4. The Convolutional Layer

### High-level idea

Instead of one big dot product across the full image, a conv layer slides a small **filter** across the image and computes a dot product at each position. This preserves spatial structure.

### How it works

1. Define a filter, e.g. **5×5×3** (must match input depth)
2. Slide the filter across the image → at each position, compute: `5×5×3 = 75 multiplications + 1 bias`
3. Each position produces **one number** → sliding across the full image produces a **2D activation map**
4. Use **multiple filters** → each produces its own activation map → stack them into a 3D output volume

### Tensor shapes

```
Input:   (N, C_in,  H,  W)         — batch of images
Filters: (C_out, C_in, K_H, K_W)   — C_out filters, each of depth C_in
Bias:    (C_out,)                   — one bias per filter
Output:  (N, C_out, H', W')
```

- `N` — batch size (process multiple images at once)
- `C_out` — number of filters = number of output channels
- `H'`, `W'` — output spatial dimensions (depend on padding and stride)

### Why stack conv layers?

Stacking conv layers with ReLU activations between them lets the network learn increasingly complex features. Without nonlinear activations (ReLU), stacked conv layers collapse into a single linear operation.

```
Input → [Conv → ReLU] → [Conv → ReLU] → ... → [FC layers] → scores
```

## 5. Local Connectivity and Parameter Sharing

These two ideas are what make CNNs practical. They drastically reduce the number of parameters compared to a fully connected layer.

### Local connectivity

In a conv layer, each output neuron only connects to a **small local patch** of the input — its receptive field. It does connect across the **full depth** (all channels), but only to a spatially local region.

```
FC neuron:   sees all 32×32×3 = 3072 values
Conv neuron: sees only 5×5×3 = 75 values
```

This encodes the prior that nearby pixels are more correlated than distant ones.

### Parameter sharing

All neurons in the **same depth slice** (i.e., the same filter) share identical weights. The filter is applied at every position, not just one.

**Intuition:** If an edge detector is useful at the top-left of an image, it's probably useful everywhere. We don't need a separate edge detector for each pixel position.

**Impact on parameters:**

| Layer type | Parameters (AlexNet first layer) |
|---|---|
| Without parameter sharing | ~105 million |
| With parameter sharing | ~35,000 |

That's a **3000× reduction** in parameters for the same computation.

> **Exception — Locally-Connected Layers:** When the input has strong spatial structure (e.g. a centered face), different positions genuinely need different features. In this case, parameter sharing is relaxed and each position has its own weights. Rarely used in general-purpose CNNs.

## 6. What Do Conv Filters Learn?

Each layer learns progressively more complex patterns:

| Layer | What it learns |
|---|---|
| Linear classifier | One template per class (whole image) |
| MLP hidden layer | Bank of whole-image templates |
| **First conv layer** | Local image templates — oriented edges, opposing colors |
| **Deeper conv layers** | Larger structures — eyes, textures, object parts |

**Example:** AlexNet's first layer has 64 filters, each 3×11×11. Visualizing them reveals clear edge detectors and color-opponent filters — similar to what's found in the primary visual cortex (V1).

Deeper layer filters are harder to visualize directly but respond to increasingly abstract features.

## 7. Spatial Dimensions, Padding, and Stride

### Without padding

A filter of size K on an input of size W produces output of size `W - K + 1`.

```
Input: 7×7, Filter: 3×3 → Output: 5×5
```

**Problem:** Feature maps shrink with every layer. Deep networks would quickly reduce to nothing. Also, border pixels are "touched" far less than center pixels — information is lost at edges.

### Padding

Add zeros around the border of the input before applying the filter.

```
Output size = W - K + 1 + 2P
```

**Common setting:** `P = (K - 1) / 2` → output is the **same spatial size as the input** ("same" padding)

This also ensures border information is preserved and each position in the input contributes equally.

### Stride

Instead of sliding the filter one pixel at a time, skip S pixels between positions. This downsamples the output.

```
Output size = (W - K + 2P) / S + 1
```

### Full formula

$$H' = \frac{H - K + 2P}{S} + 1, \quad W' = \frac{W - K + 2P}{S} + 1$$

> The result must be a whole number. Non-integer outputs mean the hyperparameters don't tile the input evenly — this is invalid.

### Worked example

> Input: 3×32×32, 10 filters of size 5×5, stride 1, padding 2

| Question | Answer |
|---|---|
| Output volume | 10 × 32 × 32 |
| Learnable parameters | 10 × (3×5×5 + 1 bias) = **760** |
| Multiply-add operations | 75 ops/output × 10×32×32 outputs = **768,000** |

## 8. Convolution Summary

| Item | Detail |
|---|---|
| **Input** | C_in × H × W |
| **Weights** | C_out × C_in × K_H × K_W |
| **Bias** | C_out (one per filter) |
| **Output** | C_out × H' × W' |
| **H'** | (H - K + 2P) / S + 1 |
| **W'** | (W - K + 2P) / S + 1 |

### Common settings

| Setting | Values |
|---|---|
| Filter sizes | K = 3 (most common), 5, 1 |
| Channels | C_in, C_out ∈ {32, 64, 128, 256} — powers of 2 |
| "Same" padding | P = (K - 1) / 2 → output same size as input |
| 3×3 conv (no shrink) | K=3, P=1, S=1 |
| 5×5 conv (no shrink) | K=5, P=2, S=1 |
| 1×1 conv | K=1, P=0, S=1 — mixes channels without changing spatial size |
| Downsample by 2× | K=3, P=1, S=2 |

**Preferred practice:** Use stride 1 in conv layers and leave spatial downsampling to pooling layers (or explicit stride-2 layers). This keeps spatial downsampling as a deliberate decision rather than a side effect.

## 9. Receptive Fields and Downsampling

### Receptive field

The **receptive field** of an output neuron is the region of the input it "sees."

- Single conv layer with kernel size K → each output sees a **K×K** patch
- After L layers: **receptive field = 1 + L × (K - 1)**

```
Example: L=3 layers, K=3 → receptive field = 1 + 3×2 = 7×7
```

**Problem:** For large images (e.g. 224×224), you'd need ~112 layers of 3×3 convolutions for outputs to see the full image. That's too deep.

**Solution: Downsampling** — shrink spatial dimensions inside the network so later layers cover the full image with fewer neurons.

### Two ways to downsample

| Method | How | Notes |
|---|---|---|
| **Strided convolution** | Set S > 1 | Learned; combines downsampling with feature extraction |
| **Pooling layer** | Separate pooling op | No learnable params; explicit separation of concerns |

## 10. Other Types of Convolution

### 1D Convolution
For sequential data (audio, text, time series).
```
Input:   C_in × W
Weights: C_out × C_in × K
Output:  C_out × W'
```

### 2D Convolution (standard)
For images.
```
Input:   C_in × H × W
Weights: C_out × C_in × K × K
Output:  C_out × H' × W'
```

### 3D Convolution
For video or volumetric data (e.g. medical CT scans).
```
Input:   C_in × H × W × D
Weights: C_out × C_in × K × K × K
Output:  C_out × H' × W' × D'
```

### Dilated (Atrous) Convolution
A filter with **gaps** inserted between its elements, expanding the receptive field without adding parameters or reducing spatial resolution.

```
Standard 3×3:    x x x          Dilated (gap=1):  x . x . x
                 x x x                            . . . . .
                 x x x                            x . x . x
```

A 3×3 filter with dilation rate 2 has the same receptive field as a 5×5 filter, using the same number of parameters. Useful when you need a large receptive field without downsampling (e.g. in segmentation tasks).

## 11. Pooling Layers

### High-level idea

Pooling is a parameter-free downsampling operation. It reduces spatial size by summarizing a local region with a single number. Depth is **unchanged**.

### How it works

For each channel independently, slide a K×K window across the feature map and apply a pooling function:

- **Max pooling** — take the maximum value (most common)
- **Average pooling** — take the average

### Max pooling example

```
Input 4×4:          Output 2×2 (K=2, S=2):
1  1  2  4             6  8
5  6  7  8     →       3  4
3  2  1  0
1  2  3  4
```

Max pooling with 2×2 kernel and stride 2 → **2× downsampling** in each spatial dimension, discarding 75% of activations per channel.

### Why max pooling?

Max pooling gives **invariance to small spatial shifts** — if a feature moves slightly within the pooling window, the maximum stays the same. This makes the network more robust to exact feature location.

During backprop, gradients only flow back through the position that had the maximum value (tracked during the forward pass via "switches").

### Pooling summary

| Item | Detail |
|---|---|
| **Input** | C × H × W |
| **Output** | C × H' × W' (channels unchanged) |
| **H'** | (H - K) / S + 1 |
| **W'** | (W - K) / S + 1 |
| **Learnable params** | None |
| **Common setting** | max, K=2, S=2 → 2× downsampling |
| **Overlapping pooling** | K=3, S=2 (used in AlexNet) |

> **Modern trend:** Recent architectures reduce or eliminate pooling entirely, using strided convolutions to downsample instead. Removing pooling is especially beneficial for generative models (VAEs, GANs) which need to reconstruct spatial detail.

## 12. Translation Equivariance

### High-level idea

If you shift the input image, the output feature maps shift by the same amount. The features don't depend on *where* in the image an object appears.

### Formally

$$\text{Conv}(\text{Translate}(X)) = \text{Translate}(\text{Conv}(X))$$

This holds for both convolution and pooling.

### Why this matters

- An edge detector fires wherever there's an edge — top-left, center, bottom-right, anywhere
- The network doesn't need to learn separate detectors for each location
- Combined with parameter sharing, this is why CNNs need far fewer parameters than FC networks for images

> **Equivariance vs. Invariance:** Equivariance means the output *shifts* when the input shifts. Invariance means the output *doesn't change*. Max pooling gives local invariance (small shifts within a window). Full translation invariance typically comes from global pooling or FC layers at the end.

## 13. Architecture Design Patterns

### Standard ConvNet pattern

```
INPUT → [[CONV → RELU] × N → POOL?] × M → [FC → RELU] × K → FC
```

- N ≥ 0 (usually ≤ 3 conv layers per block)
- M ≥ 0 (number of blocks)
- K ≥ 0 (usually < 3 FC layers)

**Examples:**
```
Simple:       INPUT → CONV → RELU → FC
Intermediate: INPUT → [CONV → RELU → POOL] × 2 → FC → RELU → FC
Advanced:     INPUT → [CONV → RELU → CONV → RELU → POOL] × 3 → [FC → RELU] × 2 → FC
```

### Why stack small filters instead of one large filter?

Three 3×3 CONV layers stacked give an effective receptive field of **7×7** — the same as a single 7×7 layer. But stacking is better:

| | 3 stacked 3×3 layers | 1 single 7×7 layer |
|---|---|---|
| Effective receptive field | 7×7 | 7×7 |
| Parameters (C channels) | 3 × (3×3×C²) = **27C²** | 7×7×C² = **49C²** |
| Non-linearities | 3 ReLUs | 1 ReLU |
| Feature expressiveness | Higher | Lower |

Stacking gives more representational power with fewer parameters, at the cost of more memory for intermediate activations during backprop.

### Input sizing

- Choose input sizes divisible by 2 many times (to survive repeated 2× pooling)
- Common: 32 (CIFAR-10), 64, 96 (STL-10), 224 / 384 / 512 (ImageNet)

### Memory vs. accuracy tradeoff

Early layers produce large activation maps (e.g. 224×224×64) that consume most memory. If memory is tight, it's acceptable to use a larger filter with a larger stride *only on the first layer* to aggressively reduce early activations (e.g. 7×7, stride 2, as in AlexNet and ResNet).

## 14. FC ↔ CONV Conversion

### Key insight

FC layers and CONV layers compute the same thing — a dot product between a weight vector and a local region of the input. The only difference is connectivity structure.

- **FC layer:** connects to all activations globally
- **CONV layer:** connects to a local spatial region, with shared weights

An FC layer is equivalent to a CONV layer with a filter the same size as the input.

### FC → CONV: enabling multi-scale evaluation

Converting FC layers to CONV layers allows a network to process images **larger than it was trained on** in a single forward pass, producing a spatial grid of predictions instead of a single score.

**Example:**
- A network trained on 224×224 has `conv → pool → ...` that produces 7×7×512 before the FC layers
- Convert each FC layer to a CONV: the first FC (7×7×512 input → 4096 output) becomes a 7×7 CONV
- Feed a **384×384 image** → the convolutional backbone produces 12×12×512 → the converted FC layers produce **6×6×1000**
- This is equivalent to running the original network at **36 overlapping positions** but with shared computation — much faster than 36 separate forward passes

## 15. Notable CNN Architectures

### LeNet (1998)
- Yann LeCun — pioneering CNN for digit and zip code recognition
- Established the basic Conv → Pool → Conv → Pool → FC pattern

### AlexNet (2012)
- Krizhevsky, Sutskever, Hinton — won ImageNet by a large margin (16% vs. 26% error)
- First major CNN to use ReLU activations, dropout, and GPU training
- Popularized deep learning for computer vision
- Key innovation: stacked CONV layers before pooling (instead of CONV → POOL → CONV → POOL)

### ZFNet (2013)
- Zeiler & Fergus — won ImageNet by tweaking AlexNet's hyperparameters
- Smaller stride and filter on first layer; larger middle CONV layers
- Used visualization techniques to understand what filters learned

### VGGNet (2014)
- Simonyan & Zisserman — showed that **depth** is the critical factor for performance
- Very simple, uniform design: only 3×3 CONV (stride 1, pad 1) and 2×2 max pooling throughout
- 16–19 layers; 138M parameters
- Most parameters live in the FC layers; CONV layers do most of the compute
- Still widely used as a backbone for transfer learning

### GoogLeNet / Inception (2014)
- Szegedy et al. (Google) — won ImageNet
- Key innovation: **Inception module** — applies multiple filter sizes (1×1, 3×3, 5×5) in parallel and concatenates outputs
- Only 4M parameters vs. AlexNet's 60M — much more efficient
- Uses global average pooling instead of large FC layers at the top

### ResNet (2015)
- Kaiming He et al. (Microsoft Research) — won ImageNet, outperformed human-level accuracy
- Key innovation: **skip connections** (residual connections) — allows gradients to flow directly through the network, enabling training of very deep networks (50–152+ layers)
- Uses batch normalization throughout; no FC layers at the end
- Default choice for most practical vision tasks as of 2016

## 16. Memory Considerations

Memory is often the primary bottleneck when designing or training CNNs.

### Three sources of memory usage

| Source | What it is | Notes |
|---|---|---|
| **Activations** | Intermediate feature maps at every layer | Must be stored for backprop; largest in early layers |
| **Parameters** | Weights + gradients + optimizer state | Multiply parameter count by ~3 for training |
| **Miscellaneous** | Input batches, augmentation buffers, etc. | Implementation overhead |

### Where memory concentrates

- **Most memory:** early CONV layers (large spatial activation maps)
- **Most parameters:** final FC layers (e.g. VGGNet's FC layers hold ~100M of 138M total params)

### Quick estimate

1. Count total values across all activations
2. Multiply by 4 bytes (float32) or 8 bytes (float64)
3. Divide down: bytes → KB → MB → GB
4. Multiply by ~3 to account for gradients + optimizer state

**Primary lever:** Reduce batch size — most memory is consumed by activations, which scale linearly with batch size.
