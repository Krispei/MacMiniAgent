
## Summary

Actor-critic methods fix the core weakness of policy gradients: the gradient estimate is too noisy because it relies on a single sampled trajectory to estimate future rewards. The fix is to **learn a value function** (the "critic") that gives a better estimate of expected future rewards — replacing the noisy single-sample reward-to-go with a neural network that has seen many trajectories.

**The key insight:** Better estimates of the advantage function → lower variance gradients → more stable, efficient learning.

The "actor" (policy) decides what to do. The "critic" (value function) evaluates how good that was. The actor then updates based on the critic's feedback.

## 1. Why Actor-Critic?

**The problem with policy gradients:** Policy gradients rely on the *reward-to-go* — the sum of actual rewards seen in one trajectory — as the signal for how good each action was. This is noisy for two reasons:

1. **Sparse rewards** — if reward only comes at the end, most of the gradient is uninformative
2. **Single-sample estimates** — one trajectory is a noisy estimate of the true expected return

**Example:**

| Trajectory | Outcome | Reward |
|---|---|---|
| τ₂ | Folds only the sleeves | 0.5 |
| τ₃ | Flattens but doesn't fold | 0.5 |
| τ₄ | Folds the jacket neatly | 1.0 |

With sparse rewards and only a few samples, the policy gradient can't cleanly distinguish "mediocre" from "good" behavior. **Can we learn what is good and bad?** Yes — that's what the critic does.

## 2. Key Objects: V, Q, and Advantage

These three functions describe how good a state or action is under a given policy $\pi$.

**Value function $V^\pi(s)$**
> Expected total future reward if you start in state $s$ and follow $\pi$.

$$V^\pi(s) = \mathbb{E}_{\tau \sim \pi}\left[\sum_{t} r(s_t, a_t) \;\Big|\; s_0 = s\right]$$

**Q-function $Q^\pi(s, a)$**
> Expected total future reward if you start in state $s$, take action $a$, then follow $\pi$.

$$Q^\pi(s, a) = r(s, a) + \mathbb{E}_{s' \sim p}\left[V^\pi(s')\right]$$

**Advantage function $A^\pi(s, a)$**
> How much *better* is action $a$ compared to average behavior at state $s$?

$$A^\pi(s, a) = Q^\pi(s, a) - V^\pi(s)$$

**Useful relation:**

$$V^\pi(s) = \mathbb{E}_{a \sim \pi(\cdot|s)}\left[Q^\pi(s, a)\right]$$

**Intuitive example — learning guitar:**

Suppose policy $\pi$ plays each song equally. Current state $s_t$ = "I'm deciding what to practice." Reward = 1 if I can play it in a month, else 0.

- $V^\pi(s_t)$ = avg. prob of success across all songs (e.g., 1/3)
- $Q^\pi(s_t, a_1)$ = prob of success if I practice song $a_1$ (e.g., 0 — too hard)
- $Q^\pi(s_t, a_2)$ = prob of success if I practice song $a_2$ (e.g., 1 — easy)
- $A^\pi(s_t, a_2)$ = $1 - 1/3 = 2/3$ → song $a_2$ is much better than average

## 3. From Policy Gradient to Actor-Critic

**Starting point:** The policy gradient uses reward-to-go as an estimate of $Q^\pi$:

$$\nabla_\theta J(\theta) \approx \frac{1}{N}\sum_{i,t} \nabla_\theta \log \pi_\theta(a_{i,t}|s_{i,t}) \underbrace{\left(\sum_{t'=t}^T r(s_{i,t'}, a_{i,t'})\right)}_{\text{single-sample estimate of } Q^\pi}$$

**The actor-critic upgrade:** Replace the noisy single-sample reward-to-go with a learned $Q^\pi$ estimate:

$$\nabla_\theta J(\theta) \approx \frac{1}{N}\sum_{i,t} \nabla_\theta \log \pi_\theta(a_{i,t}|s_{i,t}) \cdot Q^\pi(s_{i,t}, a_{i,t})$$

**Add the baseline:** The best baseline is $V^\pi(s_t)$ (the average return from that state), which reduces to the **advantage function**:

$$\boxed{\nabla_\theta J(\theta) \approx \frac{1}{N}\sum_{i,t} \nabla_\theta \log \pi_\theta(a_{i,t}|s_{i,t}) \cdot A^\pi(s_{i,t}, a_{i,t})}$$

**Key result:** Better estimates of $A^\pi$ → less noisy gradients → more efficient learning.

**Practical advantage estimate:** We only need to fit $V^\pi$, then compute $A$ as:

$$A^\pi(s_t, a_t) \approx r(s_t, a_t) + \gamma V^\pi(s_{t+1}) - V^\pi(s_t)$$

This avoids fitting $Q$ separately.

**Updated RL loop:**

```
1. Initialize policy π_θ and value network V_φ
2. Run policy to collect batch of data
3. Fit V_φ to estimate expected return   ← NEW (the "critic")
4. Compute advantage estimates
5. Compute policy gradient and update θ  ← the "actor"
```

## 4. Estimating the Value Function

**Goal:** Train a neural network $\hat{V}^\pi_\phi: s \mapsto \mathbb{R}$ to predict expected future rewards from any state. This is called **policy evaluation**.

We need training targets $y_{i,t}$ (labels) to supervise $\hat{V}^\pi_\phi$. Two approaches:

---

### Monte Carlo Estimation

**Idea:** Use the actual sum of rewards from a rollout as the label.

$$y_{i,t} = \sum_{t'=t}^T r(s_{i,t'}, a_{i,t'})$$

**Procedure:**
1. Roll out trajectories under $\pi$
2. Build dataset $\{(s_{i,t},\; y_{i,t})\}$
3. Fit: $\min_\phi \sum_{i,t} \|\hat{V}^\pi_\phi(s_{i,t}) - y_{i,t}\|^2$

**Properties:**
- **Unbiased** — labels are real observed rewards, no approximation
- **High variance** — a single rollout is a noisy estimate of the true expectation

---

### Bootstrapping (TD Learning)

**Idea:** Use your current value estimate for $s_{t+1}$ as part of the label, instead of waiting for the full rollout.

$$y_{i,t} = r(s_{i,t}, a_{i,t}) + \gamma \hat{V}^\pi_\phi(s_{i,t+1})$$

> Labels are updated each gradient step as $\hat{V}^\pi_\phi$ improves — the target "moves."

**Properties:**
- **Lower variance** — only one reward step, then use a smoother $\hat{V}$ estimate
- **Biased** — the label is only as good as your current $\hat{V}$ estimate

| | Monte Carlo | Bootstrapping (TD) |
|---|---|---|
| Label source | Full rollout rewards | $r + \gamma\hat{V}(s')$ |
| Bias | None | Yes (depends on quality of $\hat{V}$) |
| Variance | High | Low |
| Requires full episode? | Yes | No |

---

### N-Step Returns

**Idea:** Take $n$ real reward steps before bootstrapping. This interpolates between the two extremes.

$$y_{i,t} = \sum_{t'=t}^{t+n-1} \gamma^{t'-t} r(s_{i,t'}, a_{i,t'}) + \gamma^n \hat{V}^\pi_\phi(s_{i,t+n})$$

- $n=1$: pure bootstrapping (TD)
- $n=T$: full Monte Carlo
- Choosing $n$ balances bias and variance

---

### Discount Factors

**Why:** In infinite-horizon settings ($T \to \infty$), the sum of rewards can blow up. Discounting forces the agent to prioritize near-term rewards over distant ones.

$$\gamma \in (0, 1), \quad y_{i,t} = r(s_{i,t}, a_{i,t}) + \gamma\, \hat{V}^\pi_\phi(s_{i,t+1})$$

- $\gamma$ close to 1: patient, cares about distant rewards
- $\gamma$ close to 0: myopic, only cares about immediate reward
- Typical values: $\gamma = 0.99$ or $0.95$

---

## 5. Full Algorithm

Putting it all together (on-policy actor-critic):

```
1. Sample batch of data {(s_{1,i}, a_{1,i}, …, s_{T,i}, a_{T,i})} from π_θ

2. Fit V̂_φ to summed rewards in data (Monte Carlo or TD targets)

3. Evaluate advantage for all (t, i):
      Â(s_{t,i}, a_{t,i}) = r(s_{t,i}, a_{t,i}) + γ V̂_φ(s_{t+1,i}) - V̂_φ(s_{t,i})

4. Compute policy gradient:
      ∇J(θ) ≈ Σ_{t,i} ∇_θ log π_θ(a_{t,i}|s_{t,i}) · Â(s_{t,i}, a_{t,i})

5. Update:  θ ← θ + α ∇J(θ)
```

> The value network is the **critic** (steps 2–3). The policy is the **actor** (steps 4–5).

## 6. Off-Policy Actor-Critic

**Motivation:** On-policy methods discard data after each update. This is expensive. Can we reuse old data?

Two approaches: (1) take multiple gradient steps per batch, (2) maintain a replay buffer of all past data.

---

### Version 1: Multiple Gradient Steps

**Idea:** Collect one batch, then apply multiple gradient updates before collecting new data. Use importance weights to correct for the policy shift.

**Modified step 4:**

$$\nabla J(\theta') \approx \sum_{t,i} \frac{\pi_{\theta'}(a_{t,i}|s_{t,i})}{\pi_\theta(a_{t,i}|s_{t,i})} \nabla_{\theta'} \log \pi_{\theta'}(a_{t,i}|s_{t,i}) \cdot \hat{A}^\pi(s_{t,i}, a_{t,i})$$

**The problem:** Advantages were estimated under the old policy $\pi_\theta$. As $\theta'$ diverges from $\theta$, the advantages become stale and inaccurate. If you update too aggressively, the policy chases outdated signal.

**Two fixes:**

| Approach | Idea | Where it appears |
|---|---|---|
| **KL constraint** | Penalize $D_{KL}(\pi_{\theta'} \| \pi_\theta) > \epsilon$ | PPO, TRPO |
| **Clipped importance weights** | Cap the ratio $\pi_{\theta'}/\pi_\theta$ to prevent large updates | PPO clip |

> PPO (Proximal Policy Optimization) is the practical algorithm built on these ideas — one of the most widely used RL algorithms today.

---

### Version 2: Replay Buffers

**Idea:** Instead of discarding old data, store all past transitions in a **replay buffer** and sample random minibatches from it for each update.

```
Replay buffer = {(s_i, a_i, r_i, s'_i)} — all past (state, action, reward, next state) tuples
```

**Algorithm:**

```
Loop:
  1. Collect transition (s_i, a_i, r_i, s'_i) from π_θ
     Add to replay buffer B

  2. Sample random minibatch from B

  3. Fit value function on minibatch using TD targets:
        y_i = r_i + γ V̂_φ(s'_i)

  4. Update policy using off-policy gradient on minibatch
```

**Key difference from Version 1:** The data now comes from many different past policies — not just the most recent one. This requires more careful handling:

- **Value function**: Must use TD bootstrapping (not MC), since we don't have full on-policy rollouts
- **Policy update**: Use reparameterization trick or a Q-function-based update rather than raw policy gradient

**Practical example — Soft Actor-Critic (SAC):**

SAC (Haarnoja et al., 2018) is the standard practical replay-buffer actor-critic algorithm. Key features:
- Uses a Q-function (not V) for the critic
- Adds an **entropy bonus** to encourage exploration: $r(s, a) + \alpha \mathcal{H}(\pi(\cdot|s))$
- Uses reparameterization for the policy gradient
- Very sample efficient; widely used for continuous control tasks

---

## 7. Off-Policy Tradeoffs

| | Less Off-Policy (e.g., PPO) | More Off-Policy (e.g., SAC) |
|---|---|---|
| Data reuse | Low — one batch per update | High — replay buffer of all past data |
| Sample efficiency | Lower | Much higher |
| Stability | More stable, easier to tune | Can be harder to tune, less stable |
| Typical use | On-policy fine-tuning (e.g., LLM RLHF) | Continuous control, robotics |

**Rule of thumb:**
- If data collection is cheap → PPO-style (on-policy or mild off-policy)
- If data collection is expensive → SAC-style (replay buffer, high data efficiency)
