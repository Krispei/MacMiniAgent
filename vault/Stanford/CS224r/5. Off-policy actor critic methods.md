
## Motivation

Standard online actor-critic collects a batch of data, takes **one** gradient step, then discards the data. This is wasteful. Can we reuse old data?

Two strategies, in increasing order of off-policy-ness:
1. **Multiple gradient steps** on the same batch (using importance weights) → PPO
2. **Replay buffer** of all past experience → SAC

---

## Recap: Key Objects

| Object | Meaning |
|--------|---------|
| $V^\pi(s)$ | Expected future reward from state $s$, following $\pi$ |
| $Q^\pi(s, a)$ | Expected future reward from $(s,a)$, then following $\pi$ |
| $A^\pi(s, a) = Q^\pi(s,a) - V^\pi(s)$ | How much better action $a$ is vs. the policy average |

## Part 1: Multiple Gradient Steps → PPO

### The Problem with Reusing Data

In actor-critic, after collecting data from $\pi_\theta$, we compute advantages $\hat{A}^{\pi_\theta}$ and update. If we take multiple gradient steps, the policy $\pi_{\theta'}$ drifts away from $\pi_\theta$ — but the advantages were estimated under $\pi_\theta$. The gradient update becomes **stale and unreliable**.

### Importance Weights

To correct for the mismatch between the behavior policy $\pi_\theta$ and current policy $\pi_{\theta'}$, use importance sampling:

$$\tilde{J}(\theta') = \sum_{t,i} \frac{\pi_{\theta'}(a_{t,i} | s_{t,i})}{\pi_\theta(a_{t,i} | s_{t,i})} \hat{A}^{\pi_\theta}(s_{t,i}, a_{t,i})$$

This is the **surrogate objective** — a proxy for the true policy gradient that allows reusing old data. The policy is incentivized to increase probability on high-advantage actions.

**What can go wrong?** If too many gradient steps are taken, $\pi_{\theta'}$ drifts far from $\pi_\theta$, causing the importance weights to blow up and the estimates to become inaccurate.

### Two Ideas for Constraining Updates

**Idea 1 — KL Penalty** (used in LLM RLHF):
$$\mathbb{E}_{s \sim \pi_\theta} \left[ D_{KL}\left(\pi_{\theta'}(\cdot | s) \;\|\; \pi_\theta(\cdot | s)\right) \right] \leq \delta$$
Directly constrains how far the policy can move.

**Idea 2 — Clip the importance weights** (PPO Trick 1):
$$\tilde{J}(\theta') = \sum_{t,i} \text{clip}\!\left(\frac{\pi_{\theta'}}{\pi_\theta}, 1 - \epsilon, 1 + \epsilon\right) \hat{A}^{\pi_\theta}(s_{t,i}, a_{t,i})$$
Prevents the ratio from exceeding $[1-\epsilon, 1+\epsilon]$, removing the incentive for the policy to deviate significantly.

### PPO Algorithm

**Trick 1: Clip the importance weights** (see above).

**Trick 2: Take the minimum of clipped and unclipped objectives**:
$$\tilde{J}(\theta') = \sum_{t,i} \min\!\left(\frac{\pi_{\theta'}}{\pi_\theta}\hat{A}, \;\text{clip}\!\left(\frac{\pi_{\theta'}}{\pi_\theta}, 1{-}\epsilon, 1{+}\epsilon\right)\hat{A}\right)$$
The min makes the objective **pessimistic**: you don't get credit for moving the policy more than $\epsilon$ in the good direction, but you still get penalized for moving in the bad direction. This prevents the policy from gaming the clipping (e.g., when a negative advantage and a small ratio would cause clipping to spuriously improve the objective).

**Trick 3: Generalized Advantage Estimation (GAE)**

Instead of using a single-step or full Monte Carlo return to estimate the advantage, GAE mixes $n$-step returns with exponentially decaying weights:
$$\hat{A}^{\text{GAE}} = \sum_{n=1}^{N} w_n \hat{A}^{(n)}$$
- Small $n$ (early cutoff) → lower variance, higher bias
- Large $n$ (full rollout) → lower bias, higher variance
- A hyperparameter $\lambda \in [0,1]$ controls the tradeoff

**PPO Loop:**
1. Collect rollout of ~2000 timesteps from $\pi_\theta$
2. Fit $\hat{V}^\pi_\phi$ to discounted returns
3. Compute GAE advantages
4. Run $M \approx 300$ gradient steps on surrogate objective (batch size 64, $\sim$10 epochs)
5. Repeat for ~500 iterations → ~1M total timesteps

Typical hyperparameters: $\epsilon = 0.2$, batch size 64, 10 epochs per rollout.

## Part 2: Replay Buffer → SAC

### Motivation: Can We Be Even More Off-Policy?

PPO reuses one batch a few times. Can we reuse **all past data** ever collected?

Key ideas:
- Maintain a **replay buffer** of all past $(s, a, r, s')$ transitions
- Sample mini-batches from the buffer for each update
- Remove the on-policy assumption from the value function update

### The Broken Value Function Problem

If we naively fit $V^\pi$ on data from the replay buffer (which contains transitions from many different past policies), we get a value function for an **undefined mixture policy** — not the current $\pi_\theta$. The algorithm is broken.

### Fix: Fit Q(s, a) Instead of V(s)

$Q^\pi(s, a)$ takes the action as input, so it can be evaluated on off-policy $(s, a)$ pairs. We only need the current policy for the **next state's** action:

$$Q^\pi(s, a) = r(s, a) + \gamma \,\mathbb{E}_{s' \sim p(\cdot|s,a),\, \bar{a} \sim \pi_\theta(\cdot|s')}\left[Q^\pi(s', \bar{a})\right]$$

**Regression targets** using buffer transitions $(s_i, a_i, r_i, s'_i)$:
$$y_i = r(s_i, a_i) + \gamma\, Q^\pi(s'_i, \bar{a}_i), \quad \bar{a}_i \sim \pi_\theta(\cdot | s'_i)$$

The action $a_i$ comes from the buffer (past policy), but $\bar{a}_i$ is sampled from the **current policy** — this is valid.

**Why use Q instead of A?** Using Q(s,a) directly (no baseline subtraction) has higher variance, but with a large replay buffer there is much more data, so this is acceptable.

> Note: Q-function targets require sufficient **action coverage** in the buffer to be accurate.

### SAC Algorithm (Haarnoja et al., 2018)

Practical off-policy actor-critic using replay buffer:

1. Collect $(s_i, a_i, s'_i)$ from $\pi_\theta$, add to replay buffer
2. Sample mini-batch from replay buffer
3. Compute regression target $y_i = r_i + \gamma\, Q(s'_i, \bar{a}_i)$ with $\bar{a}_i \sim \pi_\theta$
4. Update $Q$-function: minimize $\|Q(s_i, a_i) - y_i\|^2$
5. Update policy $\pi_\theta$ to maximize $Q(s, \pi_\theta(s))$ (using reparameterization trick for continuous actions)
6. Repeat

SAC also adds an **entropy bonus** to the objective ($\max_\pi \mathbb{E}[\sum r_t + \alpha \mathcal{H}(\pi)]$), encouraging exploration and improving stability.

The reparameterization trick (for Gaussian policies: $a = \mu + \sigma \cdot \epsilon$, $\epsilon \sim \mathcal{N}(0,I)$) allows low-variance gradient estimates through the Q-function.

## Part 3: PPO vs. SAC

| | PPO | SAC |
|---|---|---|
| Data reuse | One batch, a few epochs | All past data (replay buffer) |
| Off-policy-ness | Less | More |
| Stability | High ("plug & play") | Lower, more hyperparameter tuning |
| Data efficiency | Low | High |
| Markov assumption | Required | Can relax with Monte Carlo returns |
| Best for | Sim-to-real, LLMs, stable settings | Real-world RL, sample-constrained settings |

**Both:** benefit from seeding with demonstrations (imitation learning).
- PPO: initialize policy weights from IL
- SAC: add demonstrations to the replay buffer

**PPO in practice:** sim-to-real locomotion, LLM RLHF (next topic).
**SAC in practice:** learning to walk from scratch in <2 hours on a real robot (Haarnoja et al., 2018); robotic manipulation with human-in-the-loop RL (HIL-SERL, Luo et al., 2024).
