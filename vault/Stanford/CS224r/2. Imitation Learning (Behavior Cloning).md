# Imitation Learning (Behavior Cloning)

> **Summary:** Imitation learning trains a policy to mimic expert demonstrations via supervised learning. The two main challenges are (1) representing *multimodal* action distributions (solved with expressive generative models like diffusion/autoregressive policies) and (2) *compounding errors* from distribution shift at deployment (addressed with online correction methods like DAgger). The algorithm can be fully offline or augmented with online interventions. No reward function is needed, but large amounts of data may be required for reliable performance.

## Terminology Recap

| Term | Definition |
|---|---|
| **State** $s_t$ | Full state of the world at time $t$ |
| **Observation** $o_t$ | What the agent observes at time $t$ (may be partial) |
| **Action** $a_t$ | Decision taken at time $t$ |
| **Trajectory** $\tau$ | Sequence $(s_1, a_1, s_2, a_2, \ldots, s_T, a_T)$ |
| **Reward** $r(s, a)$ | Scalar signal — how good is $(s, a)$? |
| **Policy** $\pi_\theta(a \mid s)$ | The learned behavior mapping states to actions |

> The policy can also condition on observation history: $\pi(a_t \mid o_{t-m:t})$, and can be represented using a generative model.

## Imitation Learning Basics

**High-level idea:** Given expert demonstrations, learn a policy by treating it as supervised learning — predict the expert's action given the state.

**Setup:**
- **Data:** Demonstrations $\mathcal{D} = \{(s_1, a_1, \ldots, s_T)\}$ sampled from unknown expert policy $\pi_{\text{expert}}$
- **Training (deterministic):** Minimize regression loss over expert actions:

$$\min_\theta \frac{1}{|\mathcal{D}|} \sum_{(s,a) \in \mathcal{D}} \|a - \hat{a}\|^2 \quad \text{where } \hat{a} = \pi_\theta(s)$$

- **Deployment:** Run the learned policy $\pi_\theta$

This is the simplest version — often called **behavior cloning (BC)**.

---

## The Multimodality Problem

**The core issue:** An $\ell_2$ regression policy outputs the *mean* of the expert data. When the data is multimodal (e.g., multiple valid actions for the same state), the mean can be a *bad* action that no expert would take.

**Example:** Human driving data where some drivers steer left and others steer right around an obstacle. The mean prediction is to drive straight into it.

> This happens frequently in practice — especially when data is collected by multiple demonstrators.

**Takeaway:** We need policies that can represent *distributions* over actions, not just point predictions.

## Expressive Policy Distributions

**Goal:** Learn $p(\text{action} \mid \text{observation})$ using expressive generative models.

### Imitation Learning — Version 1 (Expressive Policies)

0. Given expert demonstrations $\mathcal{D}$
1. Train a generative model to maximize log-likelihood of expert actions:
$$\min_\theta -\mathbb{E}_{(s,a) \sim \mathcal{D}}[\log \pi_\theta(a \mid s)]$$
2. Deploy learned policy $\pi_\theta$

### Three Approaches

| Method | How it works | Outputs |
|---|---|---|
| **Mixture of Gaussians** | Train policy to output parameters for several Gaussians (mixture density network) | $\mu_1, \sigma_1, w_1, \mu_2, \sigma_2, w_2, \ldots$ |
| **Discretize + Autoregressive** | Discretize action space, predict one dimension at a time conditioned on previous | $p(a_{t,1}),\ p(a_{t,2} \mid \hat{a}_{t,1}), \ldots$ |
| **Diffusion** | Start from noise, iteratively denoise into an action sample | Learned denoising process |

> **Key insight:** Neural network expressivity (bigger model) is *distinct* from distribution expressivity (richer output distribution). You need both — capacity in function space *and* in distribution space — to capture complex data distributions.

## Diffusion & Flow Matching

### Core Idea

Learn to transform samples from a simple distribution (Gaussian noise) into samples from the complex data distribution (expert actions).

### Why Not Direct Regression from Noise?

A naive approach — sample noise $\epsilon$, regress $f_\theta(\epsilon) \to x_i$ — fails because the model has no reason to use the noise to map to *different* datapoints. It collapses.

### Flow Matching (a form of diffusion)

Instead: learn a **vector field** $v_\theta$ for *iterative* denoising.

**Training loop:**
1. Sample datapoint $x_1 \sim \mathcal{D}$ and noise $x_0 \sim \mathcal{N}(0, I)$
2. Sample $t \sim \text{Uniform}[0, 1]$
3. Linearly interpolate: $x_t = t \cdot x_1 + (1-t) \cdot x_0$
4. Minimize: $\|v_\theta(x_t, t) - (x_1 - x_0)\|^2$

> The interpolation is crucial — it tells the model that *anywhere between noise and data* should point toward the data, creating a dense, learnable vector field.

**Test time (Euler integration):**
1. Sample noise $x_0 \sim \mathcal{N}(0, I)$
2. For $t \in \{0, \delta, 2\delta, \ldots, 1-\delta\}$:
$$x_{t+\delta} = x_t + v_\theta(x_t, t) \cdot \delta$$
3. Return $x_1$

For imitation learning: learn a *conditional* vector field — denoising actions $a_t$ conditioned on state $s_t$.

## Action Chunking

**Idea:** Instead of predicting one action per timestep, predict a **chunk** of $k$ future actions at once: $\pi(a_{t:t+k} \mid s_t)$. New decisions are made every $k$ steps rather than every step.

| | Closed-Loop (per-step) | Action Chunking |
|---|---|---|
| **Decision frequency** | Every timestep | Every $k$ timesteps |
| **Execution** | Fully closed loop | Chunk executed open-loop |
| **Re-planning** | Constant | Less frequent |

**Why it works better:**
1. **Empirically stronger performance** — smooths out noisy per-step predictions
2. **More computation budget** — policy has more time for inference between decisions

**Key references:**
- *Learning Fine-Grained Bimanual Manipulation with Low-Cost Hardware* (ALOHA)
- *Diffusion Policy: Visuomotor Policy Learning via Action Diffusion*

## Compounding Errors & Distribution Shift

### The Problem

In standard supervised learning, inputs are independent of predictions. In sequential decision-making, **predicted actions affect the next state**. Small errors push the agent into states it never saw during training, causing further errors.

$$p_{\text{expert}}(s) \neq p_\pi(s)$$

This is called **covariate shift** — the distribution of states at test time diverges from training.

### Why It Compounds

Each mistake moves the agent further from the training distribution → worse predictions → even more unfamiliar states → cascading failure.

### Naive Solution

Collect a *massive* amount of demonstration data and hope the coverage is sufficient. Works in some domains (e.g., internet-scale driving data) but is often impractical.

## DAgger & Online Interventions

### DAgger (Dataset Aggregation)

The principled solution: collect corrective data *online* in states the policy actually visits.

**Algorithm:**
1. Roll out learned policy $\pi_\theta$: visit states $s'_1, s'_2, \ldots, s'_T$
2. Query expert for the correct action at each visited state: $a^* \sim \pi_{\text{expert}}(\cdot \mid s')$
3. Aggregate corrections into dataset: $\mathcal{D} \leftarrow \mathcal{D} \cup \{(s', a^*)\}$
4. Re-train policy: $\min_\theta \mathcal{L}(\pi_\theta, \mathcal{D})$
5. Repeat

- **Pro:** Data-efficient way to learn from an expert
- **Con:** Can be challenging to query an expert while the agent has control

### Human-Gated DAgger (HG-DAgger)

A more practical variant where the **expert watches and intervenes** when the policy makes a mistake, rather than labeling every visited state.

**Algorithm:**
1. Roll out learned policy $\pi_\theta$
2. Expert watches and **takes over** at time $t$ when a mistake is detected
3. Expert provides a corrective demonstration from $t$ onward: $(s'_t, a^*_t, \ldots, s'_T)$
4. Aggregate the new demos: $\mathcal{D} \leftarrow \mathcal{D} \cup \{(s'_i, a^*_i) : i \geq t\}$
5. Re-train policy

- **Pro:** Much more natural interface — expert just takes over when needed
- **Con:** Hard to catch mistakes quickly in some domains (e.g., fast dynamics)

> **Open question:** Can we *automatically* detect when intervention is needed?

## How to Collect Demonstrations

### Natural domains
Some domains produce demonstrations as a byproduct (driving cars, writing text). Data already exists.

### Robotics-specific methods

| Method | Pros | Cons |
|---|---|---|
| **Kinesthetic teaching** (physically guiding the robot) | Easy interface | Human visible in scene |
| **Remote controllers** (teleoperation) | Interface ease varies | Can have high latency |
| **Puppeteering** (mirrored hardware) | Easy interface | Requires duplicate hardware |

### The Embodiment Gap

Can robots learn from videos of humans or animals? **It's hard.**
- Differences in appearance
- Differences in physical capabilities and degrees of freedom

Human/animal videos can't be directly imitated but may **guide exploration** when combined with reinforcement learning.

> In some domains (e.g., quadruped locomotion), collecting human demonstrations is simply not viable — motivating RL-based approaches.

### Offline Behavior Cloning (Part 1)
Train policy to mimic demonstrations using expressive generative models.

| | |
|---|---|
| ✅ No need for online data (which can be unsafe/expensive) | |
| ✅ No reward function needed | |
| ❌ May need impractically large amounts of data | |

### Online Interventions — DAgger (Part 2)
Improve policy with corrective data from an expert during deployment.

| | |
|---|---|
| ✅ More data-efficient path to reliable performance | |
| ✅ Still no reward function needed | |
| ❌ Requires interface for expert intervention | |
| ❌ No framework for self-improvement ("practicing") | |

> **Looking ahead:** Many successful methods combine imitation learning with reinforcement learning to get the best of both worlds — expert demonstrations for a warm start, RL for continued improvement.
