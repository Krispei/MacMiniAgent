# Q-Learning
*CS 224R — Value-Based RL Methods*

## Summary

Q-learning is a **value-based** RL approach that sidesteps learning an explicit policy. Instead of asking "how do I update my policy?", it asks "what is the best possible action at every state?" — and derives the policy implicitly by always acting greedily with respect to a learned Q-function. This lecture covers how to go from policy iteration to the full Q-learning algorithm (DQN), and then how to stabilize it in practice using target networks, double Q-learning, and N-step returns.

## 1. From Policy Iteration to Q-Learning

**Overview:** If you have a good Q-function, you don't need a policy gradient at all — just always take the action with the highest Q-value. This is called *policy iteration*, and pushing it further leads directly to Q-learning.

### The Key Insight

Recall:
$$Q^\pi(\mathbf{s}_t, \mathbf{a}_t) = \text{expected total reward from taking } \mathbf{a}_t \text{ in } \mathbf{s}_t \text{, then following } \pi$$

If you know $Q^\pi$, the best action is simply:
$$\arg\max_\mathbf{a}\, Q^\pi(\mathbf{s}_t, \mathbf{a})$$

This greedy action is **at least as good** as any action $\mathbf{a} \sim \pi(\cdot | \mathbf{s}_t)$, regardless of what $\pi$ is.

So we can define a new, improved policy:
$$\pi'(\mathbf{a}_t | \mathbf{s}_t) = \begin{cases} 1 & \text{if } \mathbf{a}_t = \arg\max_\mathbf{a}\, Q^\pi(\mathbf{s}_t, \mathbf{a}) \\ 0 & \text{otherwise} \end{cases}$$

### Policy Iteration Loop

Starting from off-policy actor-critic, we can strip out the policy gradient steps entirely:

| Step | What it does |
|------|-------------|
| 1. Collect data | Take action $\mathbf{a} \sim \pi(\mathbf{a}\|\mathbf{s})$, store $(\mathbf{s}, \mathbf{a}, \mathbf{s}', r)$ in replay buffer $\mathcal{R}$ |
| 2. Sample batch | Draw $\{\mathbf{s}_i, \mathbf{a}_i, r_i, \mathbf{s}'_i\}$ from $\mathcal{R}$ |
| 3. Policy evaluation | Update $\hat{Q}_\phi$ using Bellman targets *(see Section 2)* |
| 4. Policy improvement | $\pi(\mathbf{a}_t\|\mathbf{s}_t) = 1$ if $\mathbf{a}_t = \arg\max_\mathbf{a}\, \hat{Q}_\phi(\mathbf{s}_t, \mathbf{a})$ |

> **Key shift:** In step 3, instead of sampling $\mathbf{a}'$ from the current policy, we take the **max over all actions**. This means the target $y_i$ now reflects the *improved* policy directly — no separate policy update needed.

## 2. The Bellman Optimality Equation

**Overview:** The Bellman equation gives a self-consistency condition that any valid Q-function must satisfy. The *Bellman optimality equation* is the special case for the optimal policy, and it's what Q-learning targets.

### Standard Bellman Equation (any policy $\pi$)

$$Q^\pi(\mathbf{s}, \mathbf{a}) = r(\mathbf{s}, \mathbf{a}) + \gamma\, \mathbb{E}_{\mathbf{s}' \sim p(\cdot|\mathbf{s},\mathbf{a}),\, \mathbf{a}' \sim \pi(\cdot|\mathbf{s}')} \left[Q^\pi(\mathbf{s}', \mathbf{a}')\right]$$

Intuition: the Q-value of taking $\mathbf{a}$ in $\mathbf{s}$ equals the immediate reward plus the discounted expected Q-value of the next step.

### Bellman Optimality Equation (optimal policy $\pi^*$)

For the optimal policy, the expectation over actions collapses to a max:

$$Q^{\pi^*}(\mathbf{s}, \mathbf{a}) = r(\mathbf{s}, \mathbf{a}) + \gamma\, \mathbb{E}_{\mathbf{s}' \sim p(\cdot|\mathbf{s},\mathbf{a})} \left[\max_{\mathbf{a}'} Q^{\pi^*}(\mathbf{s}', \mathbf{a}')\right]$$

This gives us the Q-learning target:
$$y_i = r_i + \gamma \max_{\mathbf{a}'} \hat{Q}_\phi(\mathbf{s}'_i, \mathbf{a}')$$

When we minimize $\mathcal{L}(\phi) = \frac{1}{N}\sum_i \|\hat{Q}_\phi(\mathbf{s}_i, \mathbf{a}_i) - y_i\|^2$, we are trying to make the Bellman optimality equation hold everywhere.

### Does Q-learning converge?

- **Tabular Q-learning** (a table for every $(s,a)$): **yes**, guaranteed convergence to $Q^*$
- **With function approximation** (e.g., neural networks): **no guarantee** — can construct cases where it diverges, even with linear Q
- In practice, it can be made to work well with the tricks covered below

> **Note:** Q-learning is inherently **off-policy** — the target $y_i$ uses $\max_{\mathbf{a}'}$ (the improved policy), not the policy that collected the data. This is a feature, not a bug: data from any policy can be reused.

## 3. Data Collection: Exploration Strategies

**Overview:** Q-learning needs to have seen enough different actions to compute the max accurately. But the greedy policy only ever picks one action per state. We need deliberate exploration.

### The Problem

The target $y_i = r_i + \gamma \max_{\mathbf{a}'} \hat{Q}_\phi(\mathbf{s}'_i, \mathbf{a}')$ requires good coverage of actions $\mathbf{a}'$ to be accurate. A fully greedy policy never explores, so it may miss better actions entirely.

### Option 1: Epsilon-Greedy

$$\pi(\mathbf{a}_t | \mathbf{s}_t) = \begin{cases} 1 - \epsilon & \text{if } \mathbf{a}_t = \arg\max_\mathbf{a}\, Q_\phi(\mathbf{s}_t, \mathbf{a}) \\ \epsilon / (|\mathcal{A}| - 1) & \text{otherwise} \end{cases}$$

- With probability $\epsilon$: take a uniformly random action
- With probability $1-\epsilon$: take the greedy action
- Common practice: start with large $\epsilon$ (heavy exploration), anneal it down over training

### Option 2: Boltzmann Exploration

$$\pi(\mathbf{a}_t | \mathbf{s}_t) \propto \exp\bigl(Q_\phi(\mathbf{s}_t, \mathbf{a}_t)\bigr)$$

- Actions are sampled proportionally to their Q-values
- Higher Q-value → more likely to be chosen, but not exclusively
- Softer than epsilon-greedy; good actions are preferred but alternatives aren't ignored

## 4. Full Q-Learning Algorithm (with Replay Buffer)

**Overview:** Putting it all together — Q-learning with a replay buffer collects data from the environment, stores it, and repeatedly samples mini-batches to update the Q-network.

### Algorithm

```
repeat:
  1. Collect data {(s_i, a_i, s'_i, r_i)} using exploration policy → add to R

  repeat K times:
    2. Sample a batch (s_i, a_i, s'_i, r_i) from R
    3. Gradient step: φ ← φ - α Σ_i (dQ_φ/dφ)(s_i, a_i) · (Q_φ(s_i, a_i) - [r_i + γ max_a' Q_φ(s'_i, a')])
```

**Final policy:** $\pi(\mathbf{a}_t | \mathbf{s}_t) = 1$ if $\mathbf{a}_t = \arg\max_\mathbf{a}\, Q_\phi(\mathbf{s}_t, \mathbf{a})$, else $0$

- $K = 1$ is most common; larger $K$ is more sample-efficient but riskier
- The replay buffer allows reuse of old transitions — this is what makes it off-policy

### Why a Replay Buffer?

| Without replay buffer | With replay buffer |
|----------------------|-------------------|
| Sequential data → highly correlated | Random mini-batches → decorrelated |
| Discard data after one update | Reuse data many times |
| Less stable training | More stable, sample-efficient |

## 5. Stabilizing Q-Learning: Target Networks (DQN)

**Overview:** The update target $y_i = r_i + \gamma \max_{\mathbf{a}'} Q_\phi(\mathbf{s}'_i, \mathbf{a}')$ uses the same network $\phi$ that we're updating. This creates a *moving target* problem — the labels shift every gradient step, making training unstable.

### The Moving Target Problem

In supervised learning, labels are fixed. In Q-learning:
$$y_i = r_i + \gamma \max_{\mathbf{a}'} Q_\phi(\mathbf{s}'_i, \mathbf{a}')$$

Every update to $\phi$ changes both the prediction **and** the target. This can cause oscillations or divergence.

### Solution: Target Network

**Idea:** Freeze the parameters used to compute targets, and update them only periodically.

```
0. Save target parameters: φ' ← φ

repeat N times:
  1. Collect data, add to R

  repeat K times:
    2. Sample batch from R
    3. φ ← φ - α Σ_i (dQ_φ/dφ)(s_i, a_i) · (Q_φ(s_i, a_i) - [r_i + γ max_a' Q_φ'(s'_i, a')])
                                                                              ↑ frozen target network

(periodically: φ' ← φ)
```

- Inner loop is now effectively **supervised learning** with fixed labels
- Target network $Q_{\phi'}$ is updated every $N$ outer iterations (or with Polyak averaging: $\phi' \leftarrow \tau\phi + (1-\tau)\phi'$)

### DQN

This algorithm — Q-learning + replay buffer + target network — is the **Deep Q-Network (DQN)**.

> *Mnih et al., "Playing Atari with Deep Reinforcement Learning," 2013* — the first deep RL method.

DQN learned to play 49 Atari games from raw pixels, outperforming human-level performance on most of them (Mnih et al. 2015).

## 6. Overestimation & Double DQN

**Overview:** DQN tends to systematically **overestimate** Q-values, because it uses the same noisy network to both select and evaluate the best action. Double DQN fixes this by decoupling those two steps.

### Why Overestimation Happens

The target is:
$$y_j = r_j + \gamma \max_{\mathbf{a}'} Q_{\phi'}(\mathbf{s}'_j, \mathbf{a}'_j)$$

Note that:
$$\max_{\mathbf{a}'} Q_{\phi'}(\mathbf{s}', \mathbf{a}') = Q_{\phi'}\bigl(\mathbf{s}',\; \arg\max_{\mathbf{a}'} Q_{\phi'}(\mathbf{s}', \mathbf{a}')\bigr)$$

The **same noisy network** $Q_{\phi'}$ is used to:
- Select which action looks best (`arg max`)
- Evaluate how good that action is (the value)

If the network has noise, it will tend to pick actions where the noise is artificially high — and then evaluate those actions with that same inflated estimate. This systematically **overestimates** future values.

### Double Q-Learning

**Fix:** Decouple action selection and value evaluation using two different networks.

$$Q_{\phi_A}(\mathbf{s}, \mathbf{a}) \leftarrow r + \gamma Q_{\phi_B}\bigl(\mathbf{s}',\; \arg\max_{\mathbf{a}'} Q_{\phi_A}(\mathbf{s}', \mathbf{a}')\bigr)$$
$$Q_{\phi_B}(\mathbf{s}, \mathbf{a}) \leftarrow r + \gamma Q_{\phi_A}\bigl(\mathbf{s}',\; \arg\max_{\mathbf{a}'} Q_{\phi_B}(\mathbf{s}', \mathbf{a}')\bigr)$$

If the two networks have **independent noise**, overestimation is eliminated — the biased action selection from one network gets evaluated by the other network's unbiased estimate.

### Double DQN in Practice

We already have two networks from the target network trick — use them!

| Version | Target |
|---------|--------|
| Standard DQN | $y = r + \gamma Q_{\phi'}\bigl(\mathbf{s}',\, \arg\max_{\mathbf{a}'} Q_{\phi'}(\mathbf{s}', \mathbf{a}')\bigr)$ |
| **Double DQN** | $y = r + \gamma Q_{\phi'}\bigl(\mathbf{s}',\, \arg\max_{\mathbf{a}'} \mathbf{Q_\phi}(\mathbf{s}', \mathbf{a}')\bigr)$ |

- **Action selection:** current network $Q_\phi$
- **Value evaluation:** target network $Q_{\phi'}$

This is essentially a free improvement — no extra networks needed.

## 7. N-Step Returns

**Overview:** Standard Q-learning uses a 1-step bootstrap target. N-step returns blend actual rewards over N steps with a bootstrapped value, trading off bias vs. variance.

### The 1-Step Target

$$y_{j,t} = r_{j,t} + \gamma \max_{\mathbf{a}_{j,t+1}} Q_{\phi'}(\mathbf{s}_{j,t+1}, \mathbf{a}_{j,t+1})$$

- If $Q_{\phi'}$ is **bad** (early training): the $r_{j,t}$ term carries everything
- If $Q_{\phi'}$ is **good** (late training): the bootstrapped term contributes properly

### N-Step Target

Instead of bootstrapping after just one step, collect N actual rewards first:

$$y_{j,t} = \sum_{t'=t}^{t+N-1} \gamma^{t'-t} r_{j,t'} + \gamma^N \max_{\mathbf{a}_{j,t+N}} Q_{\phi'}(\mathbf{s}_{j,t+N}, \mathbf{a}_{j,t+N})$$

| Property | Effect |
|----------|--------|
| Less biased targets | Early training is faster; more accurate when $Q_{\phi'}$ is poor |
| Lower variance than MC | Doesn't need full rollouts |
| Only correct on-policy | The summed rewards came from the data-collection policy, not $\pi^*$ |

### The Off-Policy Issue

The N real rewards $r_{j,t}, \ldots, r_{j,t+N-1}$ were collected by whatever policy was running at the time — not the current policy being optimized. This introduces bias for $N > 1$.

**Practical fixes:**
- **Most common:** ignore the problem and use $N > 1$ anyway — often works fine
- Dynamically choose $N$ so only near-on-policy data is included
- Use importance sampling to correct for the distribution mismatch

## 8. Online RL Algorithm Comparison

**Overview:** Q-learning is one of several online RL algorithms. Here's how they compare, and when to use each.

### Algorithm Summary Table

| | Vanilla PG | PPO-like | Off-policy actor-critic (SAC) | **Q-learning (DQN)** |
|---|---|---|---|---|
| Data | On-policy | Technically off-policy | Off-policy + replay buffer | Off-policy + replay buffer |
| Off-policy fix | — | Importance weights | Fit $Q^\pi$, sample $\mathbf{a}$ from $\pi$ | Fit $Q^*$ with TD |
| Value function | None | $V^\pi$ | $Q^\pi$ | $Q^*$ |
| Goodness estimate | $\sum r_t - b$ | $\hat{A}^\pi$ (MC/TD/GAE) | TD or n-step | TD or n-step |
| Policy update | $(\nabla \log \pi)(\sum r_t - b)$ | $(\nabla \log \pi)\hat{A}^\pi$ | $(\nabla \log \pi)\hat{Q}^\pi$ | $\max_\mathbf{a} \hat{Q}^*(\mathbf{s}, \mathbf{a})$ |

### When to Use Each

| Algorithm | Use when... |
|-----------|------------|
| **PPO & variants** | You want stability and ease of use; data efficiency doesn't matter |
| **DQN & variants** | You have discrete actions or low-dimensional continuous actions |
| **SAC & variants** | You need maximum data efficiency; willing to tune hyperparameters |
